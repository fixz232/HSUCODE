# Product

## Register

product

## Users

HSUCODE serves developers and technical power users who want to run an autonomous AI agent directly on Android. They work across conversations, projects, terminal sessions, agent teams, and long-running goals, often while checking progress from a phone-sized screen.

Their primary job is to give the agent a task, understand what it is doing, intervene when necessary, and verify the result without losing context.

## Product Purpose

HSUCODE brings a capable, tool-using development agent to Android, including project workspaces, terminal access, memory, scheduled work, multi-agent collaboration, and model-provider flexibility.

Success means users can move from intent to a verified result while always understanding the active project, agent state, permission scope, cost, and produced changes.

## Brand Personality

Restrained, dependable, alive.

The core work surface should feel calm and precise. Pixel-office elements may add warmth and character around agent activity, but must not turn routine workflows into a game or compete with task information.

## Anti-references

- A generic ChatGPT clone where every capability is hidden behind the message box.
- A crowded Android settings app made from an undifferentiated list of rows.
- A game-like pixel interface that obscures execution details or slows repeated work.
- A decorative SaaS dashboard dominated by cards, gradients, oversized metrics, or excessive animation.
- A terminal imitation that sacrifices readability, touch ergonomics, or accessibility for visual flavor.

## Design Principles

1. Keep the current task and its state visible.
2. Reveal advanced capability progressively, close to the workflow that needs it.
3. Show the agent's work, evidence, risk, and result instead of relying on reassurance.
4. Keep navigation stable across conversations, projects, goals, and agent teams.
5. Use personality at the edges; keep execution surfaces quiet and efficient.

## Accessibility & Inclusion

Target WCAG 2.2 AA contrast where applicable. Support Android font scaling, screen readers, reduced motion, and touch targets of at least 48 dp for primary interactions. Never communicate running, warning, failure, or selection state through color alone.
